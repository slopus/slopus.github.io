# Our own sidebar

![A fragment of our sidebar today](/thesis/sidebar.png)

This is part of our sidebar on a normal day. We build Happy, an open-source app for running coding agents, and we can't keep up with our own sessions.

Agents got good fast. The apps we use to work with them changed much less. Most of them, ours included, still give you a chat next to a list of sessions you track yourself.

We're keeping the layout people already know: tasks on the left, the session you're focused on in the middle, artifacts on the right.

![Tasks and inbox on the left, the focused session in the middle, artifacts on the right](/thesis/layout.svg)

Almost everything inside those columns changes. Here's what we're building for.

# Review moves up a level

Sub-agents already run without anyone reading what they did. That doesn't mean review goes away. It moves up a level. You check what came out, not every step that produced it.

Part of review now is just keeping a picture of how the system works: what's running, what it touches, what it's allowed to do. Even that takes discipline. It's easy to vibecode with your eyes practically closed.

# One agent talks back to you

Every agent and every tool notifies you on its own. Ten sessions means ten sources of pings, and most of them don't need you.

You can see where this is going in how Muse, dots and Grok are pitched: one always-on agent that knows you and works in the background. We agree. Everything coming in should go through one funnel. That agent knows what you care about this week, so it ranks what comes in and only interrupts you when it matters. It also checks on things without being asked. Cheap models can now ask "is everything ok? anything new?" all day for almost nothing.

You'll still run lots of agents. Only one of them talks back to you proactively.

# Tool calls are gone. The chat log is next.

The big agent apps already fold tool calls away. At most you see a line saying what the agent is doing.

The chat log is next. Do you ever scroll up in yours?

What replaces it is still open. Maybe artifacts just become much better documents. Maybe the agent writes a plan and keeps it up to date as the work moves. Maybe it decides on its own when to clear the screen and start fresh, and when to edit what's already there. Codex, ChatGPT and T3 Code already draw charts and diagrams inline instead of walls of text. Figuring out the rest is where we'll spend most of our time.

# Everything goes back to the agent

Today you steer an agent two ways. You type in the chat, or you press buttons that run code someone wrote ahead of time.

We think most of the buttons go away. You talk, or ramble. You mark up the artifact: circle a number, cross out a paragraph, leave a note on a line. You click on something in it. None of that runs a fixed action. It goes to the agent, and the agent decides what to do. Muse already works this way.

The exceptions are things you can't take back, like sharing a secret or sending a message as you. Those stay hard permissions, and you approve them yourself.

# The sidebar becomes a browser

You still need to know where you are. When the main view keeps changing, you need something that stays put. That's the sidebar, and we're keeping it.

https://x.com/maria_rcks/status/2106620125923393849

But it stops being a list of chats. A session is really a task. It spins off more sessions, works across several repos, and ends in something you ship. So the sidebar becomes a tree of your work, and the tree holds everything: tasks, documents, previews, people.

That's browser territory. We think the AI app of the next few years will have more in common with Arc, or its open-source cousin Zen, than with today's agent orchestrators.

# Generated, inside a frame

We'll still design templates, and parts of the screen will still be set aside for specific things. But more and more of what fills them will be generated: the sidebar, the chat, the artifacts. People already ask agents for charts, diagrams and small apps, and get them.

# Teams

Multiplayer is still early everywhere. ChatGPT has [group chats](https://openai.com/index/group-chats-in-chatgpt/), and Anthropic put Claude into Slack channels with [Claude Tag](https://www.anthropic.com/news/introducing-claude-tag). Both are a group of people talking to one AI.

Our version is simple. A team that trusts each other runs a [shared server](https://happy.engineering/desktop/docs/multiplayer/), and everyone connects to it with their own account. The projects and sessions on it belong to the team. OpenClaw [does the same](https://docs.openclaw.ai/gateway/security): one server per group of people who trust each other.

It works. But signing in only tells the server who you are. It doesn't keep teammates out of each other's stuff: anyone who can steer an agent can make it do anything that agent can do. If people shouldn't see each other's credentials, today the answer is a separate server. Making one shared agent safe for a whole company is the hard part. We don't have it yet, and as far as we can tell nobody else does either.

# Permissions need standards

The agent logs into your computers and accounts, and it hands some of that access to its sub-agents. How much should it hold? How does a service know it's acting for you? How do you check what it did? One company can't settle that. It needs standards.

https://x.com/nikitabier/status/2107157904168239416

Those are starting to show up. Meta and Sierra just announced the [Personal Agent Protocol](https://sierra.ai/blog/introducing-personal-agent-protocol), an open standard for personal agents to prove they act for a real user. We'll build on standards like that rather than invent our own.

# Aren't there a lot of these already?

Why not just use Muse, dots, Grok, T3 Code or Conductor?

The labs each run their own models. We like using Muse, but it runs Meta's model, and Muse Spark isn't a frontier model. Happy is open source, works with models from every provider, and you can host it yourself. When a better model ships, you switch without moving your whole setup.

The apps differ by what they focus on. Our bet is the interface: a generated sidebar and chat, artifacts instead of a chat log, and multiplayer.

We think this is the last fun piece of software to build for humans. Everyone is going to need a way to talk to AI. We're building ours for builders, artists, and anyone who needs frontier intelligence and agrees with the ideas above.

Meta got in touch about an internal pilot because their engineers kept asking to use Happy at work. We hope enough other people feel the same way to give Happy a shot.
