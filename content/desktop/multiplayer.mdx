# Multiplayer & Teams

A team is several people on one Happy Agent. It runs on a server you control. Each member reaches it from their own Desktop with their own Happy Social sign-in, and pairs their own phone.

## How it works

- **Sign-in.** Each member connects a Happy Social account in Desktop (**Settings → Account → Connect account**). Their Desktop then gets a short-lived token for the team. The server checks it on every request, health included: right signature, right team, not expired. Anything else gets the same `401`.
- **Transport.** Tailcat is WireGuard without a Tailscale account. The server's address encodes its WireGuard public key, so only the server can answer at it, and traffic is encrypted between each member's machine and the server. Tailscale's free DERP relays introduce the two sides and carry traffic when no direct path through NAT works; they see addresses and timing, not content. The server needs no open port. Tailcat is not authentication: knowing the address gets you only as far as the sign-in check. See [how the connection works](/guides/remote-server/#how-the-connection-works).
- **Phones.** Each member pairs their own phone from **Settings → Mobile Access** while the team server is selected. Pairings and drafts are kept per member, and sync is end-to-end encrypted.
- **Shared work.** Everyone sees the same projects and sessions. Before each message, the agent is told who sent it, by name and email. That tells the agent who is talking; it grants nothing. Drafts and the order of each person's task list stay their own.
- **Provider accounts.** The Claude, Codex, and Grok sign-ins belong to the server's service account. Every member's work runs on those accounts and their limits; members' own subscriptions are not used.
- **Sandbox and review.** Every command runs under the same OS sandbox and Auto review as on your own machine. Members pick a session's permission mode, including Full access. On Ubuntu 24.04, an administrator first grants the daemon executable an AppArmor namespace allowance.
- **Owner.** The person who created the team is its owner. Only the owner can rename the installation or turn global skills on and off. Otherwise members have the same access.

## Set up a team

Ask the [Chief of Staff](/chief-of-staff/):

> Create a team called Acme on my server `ubuntu@203.0.113.10`.

It does this in order, and asks for invitations last:

1. **Your account.** Connect Happy Social in **Settings → Account** and bind an email. Any address you can read works.
2. **The server.** Install Happy Agent with a service account and its own provider sign-ins, as in [the remote server guide](/guides/remote-server/), and turn on Tailcat to get the server's address.
3. **The team.** Create it with a name and that address. You become its administrator.
4. **Team mode.** Switch the server to team mode with the team's ID. It then accepts only Happy Social tokens for that team, and keeps no local socket or token.
5. **Verify.** Connect from your Desktop and run a real task in a throwaway project.
6. **Invite** members by email. An invitation grants ordinary membership.

The server's `happy.toml` in team mode:

```toml
[feature.team]
enabled = true
host = "127.0.0.1"
port = 3000
workos_organization_id = "org_..."
owner_workos_user_id = "user_..."
workos_client_id = "client_..."

[feature.tailcat]
enabled = true
port = 24779
```

`host = "127.0.0.1"` keeps the server off the network except through Tailcat. A team server rejects a `[profile]` section: each member makes their own profile when they first connect.

**Joining.** Accept the email invitation, connect Happy Social in Desktop with that email, then ask your Chief of Staff to connect to the team.

**Leaving.** Happy has no remove-member action yet. Stopping the server cuts everyone off at once.

## Share your own computer

You can let someone use the Happy Agent on your own machine. You probably shouldn't, unless it is family or someone you would hand your unlocked laptop to.

The only way today is to give them your connection: turn on Tailcat ("Turn on Tailcat" to the Chief of Staff), then privately send them the address, the port, and your API token from `~/.happy/agent/token`. They add it as a `[connections.<id>]` entry on their machine, as in [step 9](/guides/remote-server/#9-add-it-to-desktop).

They are then you:

- **Everything is shared.** Your projects, sessions, Chief of Staff, settings, and profile. The agent cannot tell you apart.
- **Your accounts pay.** Their work runs on your Claude, Codex, and Grok subscriptions, your Git identity, and whatever the projects can push to.
- **The sandbox is their choice.** In Auto, commands cannot write outside the workspace, reach unlisted domains, or read credential folders such as `~/.ssh`, `~/.aws`, `~/.claude`, and `~/.codex`. They can still read the rest of your home folder, and they can switch any session to Full access, which removes the sandbox. MCP servers always run outside it.

There is no per-session invite. Team mode on your own machine gives each person their own identity, but it turns off the local socket your own Desktop uses, so it belongs on a separate machine.

**To revoke:** ask the Chief of Staff to turn off Tailcat, which closes the connection at once. Then set a new `[api] token` in your `happy.toml` and restart Happy Agent; the old token stops working. Turning Tailcat back on restores the same address, so rotate the token before you do.
