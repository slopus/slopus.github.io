# Multiplayer & Teams

Run one Happy Agent for your whole team: a self-hosted coding agent server with Claude, Codex, and Grok, on a machine you control. Each member signs in with their own Happy Social account from Happy Desktop, pairs their own phone, and works in shared projects and sessions, under the same sandbox and review rules as on a personal machine. The server is an ordinary [remote server](/guides/remote-server/) switched into team mode.

## How it works

- **Sign-in.** Each member connects their Happy Social account in Desktop (**Settings → Account → Connect account**), which signs in through WorkOS. Their Desktop then gets a short-lived WorkOS token for the team. The server checks it on every request, health included: right signature, right team, not expired. Anything else gets the same `401`. [How team sign-in works](/workos/), and how to use your own identity provider instead.
- **Transport.** Tailcat is WireGuard without a Tailscale account: no open port, traffic encrypted end to end, and Tailscale's free relays see addresses and timing, not content. The address carries a pre-shared key, so keep it private; even with it, a stranger gets only as far as the sign-in check. See [how Happy uses Tailcat](/tailcat/).
- **Phones.** Each member pairs their own phone from **Settings → Mobile Access** while the team server is selected. Phones go through Happy's relay, not Tailcat: the server publishes each member's sessions to their own Happy account, end-to-end encrypted, so the phone can read them even while the server is offline. Drafts stay per member.
- **Shared work.** Everyone sees the same projects and sessions. Whenever the speaker changes, the agent is told who it is, by name and email. That tells the agent who is talking; it grants nothing. Drafts and the order of each person's task list stay their own.
- **Provider accounts.** The Claude, Codex, and Grok sign-ins belong to the server's service account. Every member's work runs on those accounts and their limits; members' own subscriptions are not used.
- **Sandbox and review.** The rules are the ones on your own machine. Read only, Workspace write, and Auto, the default, run every command inside the OS sandbox; in Auto, an action that would cross it is reviewed first, one action at a time. Full access removes the sandbox, and any member can switch a session to it. On Ubuntu 24.04, an administrator first grants the daemon executable an AppArmor namespace allowance.
- **Owner.** The person who created the team is its owner. Only the owner can rename the installation, turn global skills on and off, or archive another member's task. Otherwise members have the same access.

## Set up a team

Ask the [Chief of Staff](/chief-of-staff/):

> Create a team called Acme on my server `ubuntu@203.0.113.10`.

It confirms your Happy Social account, installs Happy Agent on the server as in [the remote server guide](/guides/remote-server/), creates the team, switches the server to team mode, and runs a real task from your Desktop. Only then does it ask whom to invite. In team mode the server accepts only Happy Social sign-ins for that team, listens only through Tailcat, and keeps no local socket or token. Every step is in the public recipe, [Create and deploy a Happy team](https://github.com/slopus/happy-agent/blob/main/docs/recipe/deploy-happy-team.md).

**Joining.** Accept the email invitation, connect Happy Social in Desktop with that email, then ask your Chief of Staff to connect to the team.

**Leaving.** We haven't built a remove-member action yet. Stopping the server cuts everyone off at once.

## Share your own computer

You can let someone use the Happy Agent on your own machine. You probably shouldn't, unless it is family or someone you would hand your unlocked laptop to.

The only way today is to give them your connection: turn on Tailcat ("Turn on Tailcat" to the Chief of Staff), then privately send them the address, the port, and your API token from `~/.happy/agent/token`. They add it as a `[connections.<id>]` entry on their machine, or ask their Chief of Staff to add the connection.

They are then you:

- **Everything is shared.** Your projects, sessions, Chief of Staff, settings, and profile. The agent cannot tell you apart.
- **Your accounts pay.** Their work runs on your Claude, Codex, and Grok subscriptions, your Git identity, and whatever the projects can push to.
- **The sandbox is their choice.** In Auto, shell commands cannot write outside the workspace, reach unlisted domains, or read credential folders such as `~/.ssh`, `~/.aws`, `~/.claude`, and `~/.codex`; the agent's file tools can still read them, and the rest of your home folder. They can switch any session to Full access, which removes the sandbox. MCP servers always run outside it.

There is no per-session invite. Team mode on your own machine gives each person their own identity, but it turns off the local socket your own Desktop uses, so it belongs on a separate machine.

**To revoke:** ask the Chief of Staff to turn off Tailcat, which closes the connection at once. Then set a new `[api] token` in your `happy.toml` and restart Happy Agent; the old token stops working. Turning Tailcat back on restores the same address, so rotate the token before you do.
