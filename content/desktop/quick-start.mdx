# Quick Start

You need macOS, Windows, or Linux, and at least one of Claude Code, Codex, or the Grok CLI signed in on the machine.

## Install

Download from the [latest release](https://github.com/slopus/happy-desktop/releases/latest) (macOS, Windows, or Linux), or use Homebrew on macOS or Linux:

```sh
brew install --cask slopus/tap/happy
```

On macOS, open **Happy** from Applications or Spotlight. On Linux, launch it with `happy-desktop`; it needs a graphical session and FUSE.

If Windows SmartScreen says "Windows protected your PC", click **More info → Run anyway**. The installer is signed; SmartScreen warns about new releases until they build up reputation.

Open the app. It starts its own agent runtime and finds the provider sign-ins. There is no key to paste.

## First project

After you sign in to a model and pair your phone or skip it, onboarding opens the [Chief of Staff](/chief-of-staff/) with a draft ready to send. Send it, or ask in your own words:

```chief-of-staff get set up
Help me get started with Happy
```

With your go-ahead it lists recent Claude Code and Codex project folders (paths only, no conversation text), imports the one you pick or creates a new project, and agrees one small first change with you. It does not commit, push, or deploy on its own.

## First session

Open the project and start a session with any model you are signed in to. New sessions run in **Auto**: reads and workspace edits are free, everything else is sandboxed, and actions that cross the boundary are reviewed automatically. The session belongs to the runtime; closing the app does not stop it.

## Pair your phone

**Settings → Mobile Access**, or accept the offer during onboarding. Install the [Happy phone app](/mobile-app/) from the App Store or Google Play, scan the device QR, approve on the phone.

## Where things live

| Path | Contents |
| --- | --- |
| `~/Happy/Config/happy.toml` (macOS), `~/happy/config/happy.toml` (Linux) | Configuration, written with comments on first start |
| `AGENTS.md` beside it | Instructions every agent reads on every project |
| `~/Happy/Workspaces` (macOS), `~/happy/workspaces` (Linux) | Managed workspaces, one worktree each |
| `~/.happy/agent` | Runtime state: sessions, logs, socket, token |

Do not delete `~/.happy` to fix a problem. It holds sessions, configuration, and account state.
