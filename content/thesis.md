# Our own sidebar

![A fragment of our sidebar today](/thesis/sidebar.png)

This is part of our sidebar on a normal day. We build Happy, an open-source app for running coding agents, and we can't keep up with our own sessions.

Agents got good fast. The apps we use to work with them changed much less. Most of them, ours included, still give you a chat next to a list of sessions you keep track of yourself.

We're keeping the layout people already know: tasks on the left, the session you're focused on in the middle, artifacts on the right. What changes is what goes inside each column.

![Your agent at the top of the sidebar with a tree of tasks below it, the focused session as one living page in the middle, artifacts on the right](/thesis/layout.svg)

# Review moves up

Sub-agents already run without anyone reading what they did. Tool calls left the chat too. The big agent apps fold them away, and at most you get a line saying what the agent is doing.

Code review is going the same way. People don't read every line anymore. They read the changes that matter, and tools are being built for exactly that. [Graphite's Code Tours](https://graphite.com/blog/code-tours) walk you through a pull request in order. [CodeRabbit](https://www.coderabbit.ai/triage) ranks which pull requests need a human first.

Review doesn't go away. It moves up a level. A big part of it now is just keeping a picture of how the system works: what's running, what it touches, what it's allowed to do. Even that takes discipline. It's easy to vibecode with your eyes practically closed.

# The chat log is next

Tool calls left the chat. The sidebar and the chat log are next.

Do you ever scroll up in yours? Nobody does. You read the last message, maybe the one before it, and move on. So the chat doesn't need to be a log that only grows.

What replaces it is still open. Maybe artifacts just become much better documents. Maybe the agent keeps a plan up to date as the work moves. Maybe it decides when to clear the screen and start fresh, and when to edit what's already there. Codex, ChatGPT and T3 Code already draw charts and diagrams in the chat instead of walls of text. Working out the rest is where we'll spend most of our time.

# Your phone is enough

The less there is to read, the less you need a big screen. If the agent shows you the three things that matter instead of four hundred lines of log, you can steer it from your phone.

That's where Happy started: running Claude Code from your phone. So we design for the phone first.

# One agent at the top

Every agent and every tool notifies you on its own. Ten sessions means ten sources of pings, and most of them don't need you.

You can see where this is going in how Muse, dots and Grok are pitched: one always-on agent that knows you and works in the background. We agree. Everything coming in should go through one funnel.

In Happy, that agent is the first thing in your sidebar and the page you land on when you open the app. It knows what you care about this week, so it ranks what comes in and only interrupts you when it matters. It also checks on things without being asked. Cheap models can now ask "is everything ok? anything new?" all day for almost nothing.

You'll still run lots of agents. Only one of them reaches out to you on its own.

# Everything goes back to the agent

Today you steer an agent two ways. You type in the chat, or you press buttons that run code someone wrote ahead of time.

We think most of the buttons go away. You talk, or ramble. You mark up the artifact: circle a number, cross out a paragraph, leave a note on a line. You click on something in it. None of that runs a fixed action. It goes to the agent, and the agent decides what to do. Muse already works this way.

The exceptions are things you can't take back, like sharing a secret or sending a message as you. Those stay hard permissions that you approve yourself.

# As above, so below

Your agent sits at the top. Everything it's running sits below it.

When the main view keeps changing, you need something that stays put so you know where you are. That's the sidebar, and we're keeping it.

https://x.com/maria_rcks/status/2106620125923393849

But it stops being a list of chats. A session is really a task. It spins off more sessions, works across several repos, and ends in something you ship. So the sidebar becomes a map of what your agents are doing and what they've made: the tasks, the tasks under them, and the documents, previews and pull requests they produce.

# Generated, from our parts

We'll still design the app. Parts of the screen stay set aside for specific things, and the agent builds with our components: the trees in the sidebar, progress indicators on tasks, session icons, and more.

But more and more of the screen gets generated: the sidebar, and even the chat. People already ask agents for charts, diagrams and small apps, and get them.

# Teams

Multiplayer is still early everywhere. ChatGPT has [group chats](https://openai.com/index/group-chats-in-chatgpt/), and Anthropic put Claude into Slack channels with [Claude Tag](https://www.anthropic.com/news/introducing-claude-tag). Both are a group of people talking to one AI.

Our version is simple. A team that trusts each other runs a [shared server](https://happy.engineering/desktop/docs/multiplayer/), and everyone connects to it with their own account. The projects and sessions on it belong to the team. Plain OpenClaw [works the same way](https://docs.openclaw.ai/gateway/security): one server per group of people who trust each other.

That works, but signing in only tells the server who you are. Anyone who can steer an agent can make it do anything that agent can do. If teammates shouldn't see each other's credentials, today the answer is a separate server.

Keeping people apart on one server is the hard part. [OpenClaw Enterprise](https://openclaw.ai/blog/openclaw-enterprise), announced last week, goes after it. You host it yourself on Kubernetes. Each agent runs on its own with its own identity, and it doesn't inherit the permissions of whoever created it. Agents and credentials are split into separate spaces, with roles on top. It's ready for pilots. We don't have this yet.

# Permissions need standards

https://x.com/nikitabier/status/2107157904168239416

The agent logs into your computers and accounts, and it hands some of that access to its sub-agents. How much should it hold? How does a service know it's acting for you? How do you check what it did? One company can't settle that. It needs standards.

Those are starting to show up. Meta and Sierra just announced the [Personal Agent Protocol](https://sierra.ai/blog/introducing-personal-agent-protocol), an open standard for personal agents to prove they act for a real user. We'll build on standards like that rather than invent our own.

# Aren't there a lot of these already?

Why not just use Muse, dots, Grok, T3 Code or Conductor?

The labs' agents each run one company's models. We like using Muse, but it runs Meta's model, and Muse Spark isn't a frontier model. Happy is open source, works with models from every provider, and you can host it yourself. When a better model ships, you switch without moving your whole setup.

Apps like T3 Code and Conductor already let you mix providers. There the difference is what we focus on. Our next bets are the interface, meaning a generated sidebar and chat with artifacts instead of a chat log, and multiplayer.

We think this is the last fun piece of software to build for humans. Everyone is going to need a way to talk to AI. We're building ours for builders, artists, and anyone who needs frontier intelligence and agrees with the ideas above.

Meta got in touch about an internal pilot because their engineers kept asking to use Happy at work. We hope enough other people feel the same way to give Happy a shot.
